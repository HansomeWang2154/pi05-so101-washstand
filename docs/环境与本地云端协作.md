## 两层环境

项目准备工具只用Python标准库，支持Python>=3.10；可直接运行 `python3 scripts/project.py --help`。

当前选用的LeRobot源代码候选为0.6.2、Python>=3.12；它不作为本项目的自动依赖，避免初始化时自动拉取PyTorch和模型权重。已发现 `$CONDA_PREFIX/bin/python` 为Python3.12并有相关包，本次在项目 `.venv` 中复用其site-packages，不修改原环境。

`.venv` 因而依赖这台机器已有环境，并非可直接复制到云端的独立环境。真实包版本、解释器与只读检查结果保存到 environment/；CUDA和模型执行另行验收。

## 本地用法

```bash
source .venv/bin/activate
washstand doctor --gpu
washstand validate-config
washstand plan train
washstand status
make test
```

不激活环境也可使用 `.venv/bin/python scripts/project.py ...`。使用系统Python3.10时准备工具仍可运行，但不能据此判断LeRobot3.12运行时可用。

配置入口：

```bash
cp configs/local.example.json configs/local.json
```

只在核实实际设备后填写 port、leader_port、top/wrist index_or_path。local.json 被 Git 忽略；不要把密码或 Token 写入任何配置。

`configs/project.json` 是本项目配置，不是可直接传给 `lerobot-train --config_path` 的文件。`plan` 只生成带缺项说明的参数预览，没有执行器。当前未核实的设备、统计量和校准项会明确列出。

## 数据准备工具

```bash
washstand inspect-dataset data/real/washstand_v1
washstand split-dataset configs/episodes.example.json --output outputs/example_split.json
washstand plan train --split outputs/example_split.json
```

episodes.example.json 是虚构清单，只展示格式，不能用于真实训练。真实清单应记录 episode_id、session_id、layout_id、task_id；工具默认按session整体划分。若同一布局跨会话出现，需人工构造覆盖相关会话的分组键，避免泄漏。

元数据检查不解码视频、不验证Parquet内容、时间对齐或任务成功。正式G1还需要用LeRobot完整读取与视频检查。选择训练episodes不会自动重算训练集统计量；train_statistics_verified 必须基于实际检查后才改为true。

本机PyAV合成视频读写已通过；TorchCodec动态库有兼容警告，当前预览显式传 `dataset.video_backend=pyav`。这不代表所有实际视频编码均已验证。继承的LeRobot console脚本未必出现在项目venv的PATH，因此生成的预览用 `python -m lerobot.scripts...`，不依赖外部console脚本路径。

## 云端准备顺序

1. 记录云端GPU、驱动、磁盘和计费方式；代码使用相同Git提交。
2. 按冻结的LeRobot提交准备Python3.12运行时，匹配驱动选择PyTorch构建；不要直接复制本机venv。
3. 同步指定数据版本、episode划分、配置和统计；模型权重缓存独立保存。
4. 做真实batch的前向/反向、保存重载和计时，再安排长训练。
5. 部署使用训练导出的checkpoint、处理器与统计；客户端能访问的检查点路径应按远程服务实际要求填写。
6. 释放GPU前确认日志和工件已保存；训练可恢复状态与推理工件分别保留。

自动下载、远端安装、上传发布、租卡和机械臂动作不是当前 `plan` 工具的行为。后续阶段会依据已核实设备和版本实现具体启动入口。
