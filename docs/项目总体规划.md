# 项目总体规划

本文件是工作范围与架构总入口；详细工时以 [阶段实施计划](阶段实施计划.md) 为准，实际状态以 [进度看板](进度看板.md)、`../project_status.json` 和证据为准。

## 项目问题与首版交付

让 SO101 在固定的顶部/腕部双视角下，根据颜色和左右杯指令完成牙刷入杯。完整 π₀.₅ 机器人预训练权重是起点；先训练 action expert 与必要投影，具体 requires_grad 范围需实际审计。

首版必须包括真实采集、数据检查/划分、微调、部署、40 次协议化真实评测、失败分析与复现资料。颜色×左右是同一技能的四种条件，不主张开放世界或任意语言泛化。

## 系统边界

```text
本地 SO101 leader/follower + top/wrist
  → LeRobot 采集 → data/real → 离线检查与分组划分
  → 同步固定数据版本与配置 → A800 训练
  → checkpoint + processor + stats → 云端策略服务
  → 本地动作队列/固定频率执行 → 真机测试与完整记录

可选：本地 MuJoCo → 合格专家轨迹 → sim+real 对照
```

项目工具当前负责配置、元数据检查、分组清单、环境记录和命令预览。模型训练、硬件录制和策略通信沿用 LeRobot；尚未完成的接入不能用空实现宣称已可用。

## 目录分工

| 目录/文件 | 用途 |
|---|---|
| `configs/project.json` | 版本化的项目配置，非 LeRobot 原生训练配置 |
| `configs/local.example.json` | 本机设备覆盖示例；复制到忽略的 local.json 后填写 |
| `src/washstand_vla/` | 无硬件副作用的本地准备工具 |
| `scripts/project.py` | 无需安装即可使用的工具入口 |
| `tests/` | 配置、数据元信息、分组和预览行为的离线检查 |
| `environment/` | 本次实际运行的环境快照与版本约束说明 |
| `docs/` | 规划、规范、状态与操作说明 |
| `templates/` | 日志、实验、数据卡和模型卡空模板 |
| `deployment/` | 后续 LeRobot 策略服务与本地执行接入说明 |
| `sim/` | 可选MuJoCo物理场景、专家、轨迹回放与仿真数据导出；实测见仿真实施记录 |
| `data/outputs/checkpoints` | 运行数据与权重，均不进入普通 Git 提交 |

## 里程碑

I0 初始化工具 → G0 硬件/环境核查 → G1 小样本 → G2 训练保存重载与执行 → G3 正式数据 → G4 主训练 → G5 修正 → G6 评测 → G7 复现材料。

主线按技术验收推进；仿真原型与迁移对照单独排期，不替代真实基线。

2026-10-17用户明确要求现在开始仿真与数据生成，已据此启动原型，调整原先G2之后启动的顺序。真机主线不据此标记完成；当前证据见 [仿真实施记录](仿真实施记录.md)。

## 三项关键验收

1. 大规模采集前，少量真实数据能完成训练、保存/重载、远程预测和本地动作执行。
2. 长训练前，明确六维控制语义、相机顺序、时间对齐、训练 episode 清单和仅来自训练数据的统计量。
3. 正式测试前，锁定 checkpoint、处理器和推理设置；评测必须保留失败与系统中断。
