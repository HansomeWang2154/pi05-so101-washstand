# Rerun 无响应调试报告

日期：2026-10-17。阶段：G0，问题：ISSUE-020。

## 结论与现场处理

用户确认重接腕相机后机械臂跟随正常，但桌面提示 Rerun“程序无响应，请等待”。本机对照定位到 `rerun-sdk==0.33.1` 的 JPEG 压缩显示路径：同样的最小双图布局，开启显示压缩时未完成显示截图，关闭后可以显示。底层具体阻塞函数尚未定位，不能直接宣布显卡、Wayland 或相机损坏。

本机启动器已将 `--display_compressed_images=true` 改为 `false`。该参数控制 LeRobot 向 Rerun 发送的图像表示；**腕相机采集仍用 MJPG，top 仍用 YUYV**，相机格式、标定和动作参数没有改变。

用户重试顺序：先支稳从臂，在遥操作终端按 Ctrl+C，关闭旧的无响应 Rerun 窗口，再运行：

```bash
conda activate lerobot
bash outputs/real/real_20261017_162848_camera_debug/teleoperate-with-cameras.sh
```

Rerun SDK 会复用已占用默认端口的旧 viewer，重启控制程序并不保证换掉旧卡住窗口。不能只让旧窗口一直等待，也不要并行启动第二个机械臂/相机流程。缺设备启动预检和此前的线缆走线要求仍适用。

## 实际对照

所有显示测试使用已保存的图片或合成图片，没有打开相机或串口，没有发送电机目标。测试 viewer 自动退出或由测试器按已记录 PID 结束，没有终止用户控制进程。

| 条件 | 结果 | 解释边界 |
|---|---|---|
| 原双图 JPEG 记录，默认桌面 | 20 秒未生成截图 | 显示流程未完成，单独这一项不能证明具体阻塞位置 |
| 原 JPEG 记录，OpenGL、X11、指定 NVIDIA Vulkan、独立新状态目录等对照 | 仍未生成截图 | 没有证据支持仅换后端或重置布局已解决 |
| Mesa 软件 OpenGL | 退出 1，缺少 R32Float 渲染能力 | 本机这条软件渲染路线不可用 |
| 单张 64×64 未压缩图片 | 成功生成可见截图 | 基本图像显示可工作 |
| LeRobot 双图布局，64×64 原始图片 | 约 2.82 秒生成截图 | 布局本身可以显示 |
| 同样双图布局与像素，改为 JPEG 显示压缩 | 12 秒未生成截图 | 最小对照支持压缩图像路径是触发条件 |
| 已保存的真实双图，640×480，不压缩，默认 Wayland/Vulkan | 约 4.37 秒生成截图，两路可见 | 不需要为这一绕过方式修改桌面或显卡环境 |
| 默认桌面，原始双图回放与合成标量，目标 30Hz、300 次发送 | worker 退出 0；总耗时 11.00 秒（含结束等待），第 120/240 次发送后两次窗口截图成功，viewer 一直存活至测试结束 | 验证显示响应；不是实时相机 30fps、真实关节曲线或实机稳定性证据 |

成功截图的 `--screenshot-to` 测试随后发生独立的自动退出 panic：`Failed to take store hub from the Viewer`，退出码 102。已保留日志，不记为正常退出。后续常规实时 viewer 使用截图 API 两次取图，没有触发此退出 panic；测试器最后关闭自己启动的 viewer。

诊断中的一条 rayon 线程曾持续占用接近一个 CPU 核，内存约 222MB；NVIDIA 图形初始化和文件导入可以完成。不能把它解释为整个控制循环 CPU 饱和、内存耗尽或 GPU 故障。此前运动拉脱 USB 线及退出关力矩失败分别归 ISSUE-018、ISSUE-019，不能混作同一根因。

## 证据与剩余工作

本机完整证据：`outputs/real/real_20261017_165353_rerun_freeze/`，包括各条件 JSON/日志、原布局备份、最小 RRD、真实双图显示截图、连续显示截图和启动器修改前后版本。合成标量明确标记为诊断数据，没有进入真实数据集。

关闭显示压缩是已通过离线显示验证的绕过方式，压缩路径底层原因尚未修复；更大本地传输量对实际控制周期的影响仍需现场测量。用户尚未完成修改后带臂、带相机的持续重试，不能将 G0 或 G1 标为完成。

17:03:55最终只读复查未见两个串口及两路USB相机的已知节点，稳定相机别名也不在；启动器元数据分支因缺设备拒绝启动，配置类型解析仍通过。未根据节点缺失判断设备损坏。现场重接后需重新核对身份、路径和权限，再执行上述命令。
