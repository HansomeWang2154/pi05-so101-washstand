# 可选仿真与联合训练

更新：2026-10-16。用户已明确将仿真加入项目的可选范围；本文件补充主线实施计划，不替代真机验收。

具体场景建模、五关节姿态约束、脚本专家、物理成功检查、控制回放和数据导出设计见 [仿真环境与专家数据生成方案](仿真环境与专家数据生成方案.md)。该文档已完成设计整理，不表示环境或数据已实现。

## 1. 本地可以完成哪些工作

4060 Laptop 8GB 的计划目标是轻量单环境仿真：SO101、桌面、杯子、牙刷、top/wrist 两路图像，以及脚本专家和数据导出。标准 MuJoCo 的物理步进使用 CPU，OpenGL 图像渲染由图形环境负责；这与完整 π₀.₅ 模型推理的显存要求是两回事。

可行范围是工程判断，尚未在本项目进行帧率、渲染或数据生成性能验证。需要先检查本地图形驱动、MuJoCo 安装和双视角渲染，不能承诺固定 FPS 或每小时生成数量。

| 工作 | 推荐资源 |
|---|---|
| 模型/场景搭建、关节调试、单环境专家、少量图像数据 | 本地 MuJoCo |
| 批量生成同类小场景 | 先测本地吞吐；需要时另租资源 |
| π₀.₅ 微调与完整策略推理 | A800 训练、经验证的云端推理卡 |
| 仿真闭环评测 π₀.₅ | 本地运行环境，云端预测动作，记录网络影响 |
| Isaac/LeIsaac 大场景与 RTX 渲染 | 另行核查硬件与安装；不作为本地首选 |

本地仿真仍需云端推理时，评测在线期间依然有租卡费用；脚本专家生成数据可以不加载 π₀.₅。

模型优先采用 Google DeepMind Menagerie 的 SO101，并保留来源、版本与许可证。

本地已有参考：`<local-reference>/sim/so101_tissue`，其记录称使用 MuJoCo、SO101 和 LeRobot 数据导出。但旧抽纸巾代理任务含虚拟夹持、单前视角、10Hz 和弧度数据：

- 可以参考加载模型、渲染、记录与重新读取的代码结构。
- 不能直接把代理任务轨迹混入牙刷入杯数据。
- 不修改旧任务来抹去其限制；新任务另建目录，审查真实接触、控制语义和相机。

## 3. 分层实现与停止条件

G2 真机训练/保存重载/远程执行链路通过后，若有主线节余，当前迭代中可投入最多 8h：

### S1：本地场景与接口，约 2～3h 初始检查窗口

- [ ] 加载 SO101、桌面、一个有空腔的宽杯、一支刚性牙刷代理。
- [ ] top/wrist 两路画面可保存和重读。
- [ ] 六维观测和实际控制目标可记录；验证关节单位和夹爪方向。
- [ ] 用同一组明确目标检查可达性与碰撞。

这个阶段只验收场景/接口，不宣称专家或模型成功。若图形环境或资产问题在窗口内没有进展，记录阻塞并回到主线。

### S2：一个任务的专家与轨迹检查，剩余窗口

- [ ] 状态机：接近→抓取→抬升→杯口→放入→松爪→撤臂。
- [ ] 专家可读取物体真值位姿；导出给策略的输入仍是图像、指令、本体状态。
- [ ] 松爪并撤臂后，牙刷受物理支撑并稳定保持约定时间。
- [ ] 在几个不同初始位置生成少量成功轨迹；目标起点可设 20 条，不承诺 8h 内一定达到。
- [ ] 用保存的控制目标从同一初始状态重新执行，验证成功；不能用逐帧设 qpos 的方式冒充控制回放。
- [ ] LeRobotDataset 重读并检查图像、state/action、指令和边界。

达不到验收时交付明确标注的原型，暂不用于训练。初始窗口达到上限后，后续投入另行排期。

### S3：合格数据与迁移对照，另计工时

- [ ] 轨迹多样性扩展到与真实任务有关的位置、颜色、杯子和适度物理参数变化。
- [ ] 实测小批数据生成与读取吞吐，再决定规模；不先盲目生成上万条。
- [ ] 固定 real-train 子集和统计方案，先做 A/B 两组。
- [ ] 在真实 SO101 上按同一协议测试，报告收益、无收益或退化。

S3 涉及训练、部署和额外真实评测，不能计作只有 8h 的小原型任务。

## 4. 三种训练路线

| 路线 | 过程 | 本项目中的用途与限制 |
|---|---|---|
| Real-only | base → 真实数据微调 | 必做参照，先确认真实链路有效 |
| 阶段式 Sim→Real | base → 仿真微调 → 真实微调 | 容易分开调试；真实阶段可能覆盖仿真习得，也可能保留有用能力，需实测 |
| 混合 Sim+Real | base → 两域按来源比例采样共同微调 | 合理且有研究依据；抽样比例和跨域对齐需要控制，不要求先单独训练仿真 |

还可以混合后用少量真实数据收尾，但这是额外训练阶段，首版不默认增加。

不存在所有项目都必须采用的顺序。针对已有机器人预训练的 π₀.₅，建议先有 Real-only 基线，再增加 Sim+Real 一组；Sim→Real 作为后续第三组。选择混合是为了控制本项目实验数量和工作量，不是预言它必然优于阶段式。

阶段式更适合真实数据尚未准备好、仿真规模较大或两域差异需分开诊断的情况；混合更适合两域数据已具备、希望持续保留真实样本约束的情况。两者都可能有负迁移。

## 5. 混合训练的五项要求

### 控制语义

首版采用同一个 SO101 和同一六维关节目标接口。统一关节顺序、符号、单位、夹爪范围、绝对/相对动作和控制周期。不能把 Panda 末端动作或旧双臂数据直接拼进去。

### 样本来源比例

不要把两份目录合并后依赖默认均匀帧抽样：大量仿真帧会改变训练来源比例。显式记录真实样本概率 p_real 和仿真样本概率 p_sim。

本项目初次候选可设 real:sim=1:1，例如一个 batch 中各半，或按来源概率取样。比例只是待验证起点，实际记录有效抽样次数；不声称它是通用最优。每域内按 episode、时间窗口或帧取样也必须记录，避免长轨迹无意获得更大权重。

可以通过批次来源比例或显式 loss 权重控制两域贡献；若两者都用，要记录有效合成权重，避免无意重复加权。

### 归一化

统一物理坐标后使用一致处理器。不能让同一个归一化数字在 sim/real 表示不同关节角却不加区分。主对照优先保持统计方案不变，例如由真实训练集拟合公共统计用于两域，并检查仿真超范围/裁剪；若改为训练域联合统计，声明来源权重并承认统计也发生变化。

### 视觉与策略可见信息

相机的 top/wrist 含义、顺序、视角和裁剪尽量贴近；不要求照片级完全一致。专家可以读取物体位姿，学习策略不能额外获得真机没有的物体真值或成功标签。

### 数据版本与评测

仿真与真实数据分开版本化、分开训练/验证划分，sampler 决定训练组合。真实测试不参与选择生成范围、混合比例或归一化。

## 6. 如何判断仿真是否有价值

优先对比：

```text
相同基础权重 ── real-train ── A
           └── sim-train + 同一 real-train ── B
```

两组使用相同真实数据、架构、可训练参数、选择规则和真实评测协议。记录总训练步数、真实/仿真曝光次数与 GPU 时间；固定总更新数时真实曝光量可能不同，固定真实曝光量时总计算又可能不同，需说明所控制的变量。

先问同一真实数据量下真实成功率是否改善，再讨论是否减少了真实采集需求。若要声称节省示范，还需多档真实数据量的实验。不能仅凭更低训练 loss、更高仿真成功率或一条真机视频作结论。
