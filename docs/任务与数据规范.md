# 任务与数据规范

## 1. 标准任务

已确认设备：SO101 leader 主臂和 follower 从臂，顶部相机和腕部相机。

场景：干燥桌面、两支颜色可区分的牙刷、两个宽口杯。左右按固定的顶部相机画面定义；相机固定、画面不镜像。正式测试前给杯子加稳定可辨别的标记，确认语言左右不会因旋转画面混淆。

| ID | 指令 | 条件 |
|---|---|---|
| red_left | Put the red toothbrush into the left cup. | 红牙刷、左杯 |
| red_right | Put the red toothbrush into the right cup. | 红牙刷、右杯 |
| blue_left | Put the blue toothbrush into the left cup. | 蓝牙刷、左杯 |
| blue_right | Put the blue toothbrush into the right cup. | 蓝牙刷、右杯 |

标准版本每个条件起步约 20～30 条成功示范，总计 80～120 条，再根据质量和覆盖调整。10～20 条试采只有在与最终相机、动作和任务规范一致时才可纳入正式数据。

最小版本保留 red_left、red_right，两支牙刷仍可同时存在作为干扰。不能只采“红→左、蓝→右”，否则颜色与目标绑定，难以判断模型使用了哪部分指令。

牙膏、更换新物体和多步骤整理均为后续扩展，不纳入首版必须完成范围。

## 2. 成功判定

一次尝试同时满足：

1. 选择并移动了指定牙刷。
2. 牙刷进入指定杯子，由杯子支撑；不要求整支低于杯口。
3. 夹爪已松开并撤离目标，牙刷稳定保持至少 2 秒。
4. 错误物体未被错误收纳；无人工辅助完成。

开发阶段确定单次时间上限，例如 45 秒；正式评测前锁定。到时未完成、人工干预、错误物体/容器、杯子翻倒或物体掉落均计失败，并记录具体原因。通信和系统失败单独标记，但不从整系统成功率中悄悄删除。

## 3. 输入和输出契约

| 项目 | 计划 | 正式采集前必须实查 |
|---|---|---|
| 图像 | 固定顶部 top + 腕部 wrist RGB | 名称、顺序、镜像、尺寸、曝光、时间戳 |
| state | SO101 六维观测 | 关节顺序、驱动 API 单位、夹爪含义 |
| action | 同六维的发送目标位置 | 绝对/相对、单位、夹爪范围、目标与当前时刻关系 |
| 指令 | 上述固定英文任务字符串 | episode/task 映射正确，客户端实际传入 |
| 控制频率 | 先试 30Hz，必要时固定降到稳定频率 | 摄像机/串口/写盘能维持，丢帧与抖动可统计 |
| 模型处理 | π₀.₅ 自身处理器 | 图像 resize/padding、state/action 统计与逆变换 |

关节顺序参考：

```text
shoulder_pan.pos
shoulder_lift.pos
elbow_flex.pos
wrist_flex.pos
wrist_roll.pos
gripper.pos
```

名称以实际 LeRobot 数据 feature 清单为准。不要默认所有数值是弧度：驱动可能使用角度或标定后的数值，夹爪常有独立范围。将 `use_degrees`、校准版本和实际单位写入 metadata。

记录观测 state 与发出的 action；不能把实际 qpos 直接冒充目标控制指令。模型内部的 32 维 padding 由实现处理，真实机器人接口仍为六维，不能发送 32 维动作。

## 4. 数据检查

- 每条轨迹包括开始状态、接近、抓取、运输、入杯、释放和撤臂。
- 试采先检查开始/抓取/释放/结束关键帧与轨迹曲线。
- 全量检查字段缺失、NaN/Inf、重复/倒退时间戳、视频可解码、帧数对应、episode 边界。
- 观察/action 曲线检查异常突跳、夹爪方向、机器人限位及时间错位。
- 动作 chunk 不跨 episode 读取；边界 padding 和 loss mask 以实现实查。
- 训练与部署只使用一套匹配的预处理与后处理，避免重复归一化或反归一化。
- 默认 QUANTILES 路线需要 q01/q99；统计量只来自训练部分。若更换归一化方案，重新训练并记录，不在部署时单独切换。

## 5. 划分与布局

1. 先将采集布局分组；同一布局/会话的相关轨迹放同一侧。
2. 训练/验证按整条 episode 分组，建议起点约 80%/20%，保持指令均衡，实际数量写入清单。
3. 验证用于选 checkpoint；正式测试通过新采的真实 rollout 完成。
4. 从第一天预留测试布局，不把模型正式测试失败样本反复补进训练后继续报同一份测试结果。
5. 第一版只选一个留出变化：例如训练可达区域内、训练未覆盖的位置带；任务、物体、相机和灯光先保持一致。

“训练分布内新布局”与“留出位置范围”分别报告。有限样本和有限指令不用于宣称通用 VLA 或开放世界泛化。

本地是数据主副本。云端仅同步实际训练需要的数据版本；视频与 checkpoint 不放进普通 Git 提交。

## 7. 可选仿真数据的额外约束

- 仿真与真实数据分开存储，额外标明 `source=sim/real`、场景版本、物理参数与随机种子。
- 进入联合训练前，转换为同一六维关节目标语义、顺序、方向、单位、夹爪范围及控制周期。
- 同时保留原始仿真 `qpos`、发送 `ctrl/target` 与转换后的 action，便于审查。
- 两域相机均按 top/wrist 的语义顺序输入；视角、视场、图像处理尽量贴近，允许外观有差异，不要求像素完全一致。
- 禁止将两个来源各自压到 [-1,1] 后，不核对物理对应就拼接；首版用统一物理坐标和一致的处理器链。
- 原则上固定同一统计方案做对照；可从 real-train 拟合公共统计用于两域，但需检查仿真超范围与裁剪比例。若需联合估计，则仅使用两域训练数据、预先声明来源权重，并把统计变化记录为额外实验因素。
- 如果采用分域归一化，必须确保模型/推理有匹配的域处理机制并记录；首版不默认采用。
- 两域分别划分训练/验证；仿真生成范围不能依据最终真实测试结果反复定制。
- 杯内空腔、抓取、重力和释放后稳定条件必须实际有效；靠瞬移、固定绑定或逐帧写入物体位姿得到的成功，只能作接口代理测试，不能作为合格专家轨迹。
