## 4. 真机/数据侧交付，训练侧接收

真机侧产出实测动作/相机契约和候选分组清单，训练侧在使用前复核并冻结；训练统计由训练/数据处理负责人实际计算或核验，不能只接收一句“数据已采完”。

1. 固定数据版本与路径、实际episode/task清单、保留/排除记录、全量QA报告；先10～20条试采，先检查其中3～5条。
2. 六维关节名称/顺序、state/action单位、绝对目标语义、夹爪范围、校准版本、控制频率与`O_t/A_t`关系。
3. top/wrist名称、实际图像设置、镜像/方向、场景图和与模型图像输入的映射。
4. 完整session/layout组的train/validation清单、预留正式测试布局、采集与LeRobot代码版本。
5. 训练统计来源episode、q01/q99实际计算过程/结果、归一化/处理器链；缺失时保持未验证，由训练侧补齐后再更新状态。

接收后把数据/划分/统计/契约作为一次实验的只读快照。真机侧继续采集时写新会话/数据版本，不一边训练一边向训练正在读取的目录追加或覆盖metadata、视频、episode和stats。仿真新增版本同理。

## 5. G2：真实小数据的最小训练与推理验证

G1通过、真实契约和训练子集/统计来源明确后，按固定环境与有效配置做短验证。基础权重访问、实际模型revision、GPU/驱动/持久盘与费用记录在本阶段核验；本轮没有代为完成。

1. 对齐项目/LeRobot提交和依赖；记录已有dirty修改。确认完整基础权重初始化，记录权重revision、加载警告与缺失/多余参数，不能静默把随机模块当预训练模块。
2. 使用真实数据和实际π₀.₅处理器构造batch，检查图像映射、state/action维度、归一化/逆变换、动作chunk、episode边界和padding。CPU DataLoader成功不替代这一步。
3. 审计实际`requires_grad`与优化器参数组，记录expert、投影层和其他模块各自数量；不能只凭`train_expert_only=true`或视觉冻结flag认定范围正确。
4. 完成前向、反向和优化器更新，验证实际梯度范围；记录预热后单步耗时、峰值显存、有效batch/梯度累积与实际步数，再决定候选超参和预算。
5. 保存并在新进程独立重载checkpoint、预处理器、后处理器、统计量及配置；验证推理形状/单位/范围。推理工件与optimizer/scheduler等恢复训练工件分别留存。
6. 用录制观测请求实际策略服务，先验证不驱动机械臂的预测、延迟和内存；交付真机角色核验本地动作契约后，合作完成首次有限范围真机闭环。

G2是完整工程链路验证。短数据拟合或损失下降不是泛化成功率；主线G2中“训练/重载/服务”和“实际机器人执行”分别记录，双方证据齐全后才标记整个G2完成。

## 6. G4：正式训练与模型选择

G3数据版本、排除/分组清单、train-only统计冻结，且G2已有耗时/显存与重载证据后，再安排正式训练。

- 使用唯一实验ID、固定数据/权重revision/有效配置和独立输出目录；从短运行预算扩展，不把LIBERO或其他项目的步数当本任务结论。
- 首轮保持既定π₀.₅路线和expert-only；实际审计是否包含必要投影，不把它改称LoRA。
- 记录总更新数、真实/仿真样本曝光、训练耗时、费用、失败与恢复状态；不能从“预计5000步”填成“实际完成5000步”。
- checkpoint由训练/验证与开发布局结果筛选，向真机侧明确“开发候选”或“正式锁定”。40次正式测试不反复用于挑模型或补采后继续报同一测试集。
- Real-only先成立。可选Real+Sim或Sim→Real从同一基础权重分别起跑；先对齐两域动作/相机/统计并冻结采样方案，再增加实验。相同步数不等于相同真实样本曝光。

## 7. 训练 → 真机部署的交付包

用[实验模板](../templates/experiment.md)记录，推理工件完整落盘并校验后再交付，不能只有一个checkpoint目录名或可变的`latest`别名。

| 内容 | 必须说明 |
|---|---|
| 模型 | checkpoint具体路径/step/文件清单与哈希，完整基础模型ID/revision、模型配置 |
| 数据与接口 | 数据/划分/统计版本、top/wrist映射、六维动作契约、实际训练频率 |
| 处理器 | 与训练一致的预处理、后处理、归一化/逆变换和对应统计；加载方法 |
| 复现 | 项目/LeRobot提交与dirty说明、有效配置、seed、参数审计、日志与模型选择依据 |
| 实测 | 新进程重载、录制观测推理、动作形状/单位/范围；实际服务/网络下的延迟与显存证据 |
| 服务 | 启动/加载方法、实例/实际地址和端口、依赖、当前持有角色与运行/停止状态 |
| 执行设置 | 预测chunk长度、实际执行窗口、推理步数和异步队列参数；候选与实测值分开 |
| 恢复训练 | optimizer/scheduler/随机状态等恢复工件的位置，与推理必需文件分开说明 |

训练角色负责模型与策略服务，不直接占用机械臂做执行；真机角色负责客户端、校准、限幅/停止、真实时序与现场评测。推理动作仍须符合实际六维驱动契约，不能把模型内部padding直接发送给机械臂。

## 8. 多agent拆分与路径约定

训练角色可拆成版本/模块核对、数据/统计、训练配置/参数审计、重载/离线推理等明确子任务。每项任务登记负责人、文件范围、工作目录/分支、上游版本、产出和验收；子任务不各自修改全局进度，也不重复启动训练进程。

一个实验只设一个主负责人负责有效配置、GPU作业、checkpoint目录和最终汇总。并行改代码使用独立worktree；共用外部LeRobot/环境、A800显存、云盘/端口和同一数据版本仍需协调，worktree不会隔离这些资源。

后续运行日志、参数审计、原始配置与检查报告建议放`outputs/train/<experiment_id>/`，权重放该实验声明的独立持久目录；审核后的共享摘要放`environment/`或实验文档并提交。以上为路径约定，不表示本轮已经创建训练实现或生成模型工件。数据、权重、凭据和详细本机输出继续被Git忽略。
