# 公开内容与本地记录边界

共享仓库只记录技术目标、代码、可复现配置、实验事实与限制。本地个人背景、个人时间安排、真实用户目录、设备配置和原始会话分别保存在被忽略的`.private/`、`configs/local.json`、`data/`、`outputs/`中；不要把其原文放入提交说明、公开讨论或发布工件。

`.private/project-context.md`如存在，可供本机各对话/agent读取，但不能复制到共享文件。它不是克隆仓库后自带的文件，也不是远端备份。原文、历史bundle、修订映射和原始数据metadata由本地保留；原始数据生成版本不倒填为新的公开版本。

## 文档和配置

- 命令从仓库根目录运行，使用相对路径、`$HOME`、`$CONDA_PREFIX`或`$LEROBOT_SOURCE`，不嵌入某台机器的真实账户目录。
- `configs/project.json`保留通用技术参数；本机源码位置通过被忽略的local覆盖配置填写，设备身份不写入通用脚本。
- 公开计划按技术里程碑描述，个人执行安排仅在本地记录。
- 原始项目修订的精确标识和迁移映射可保留本地；公开摘要如使用`local-revision-*`，它是审计别名，不能当作Git提交SHA。外部依赖和资产来源SHA仍保留。

## 发布检查

```bash
make install-hooks
make privacy-check
make privacy-history-check
```

`privacy-check`检查拟提交树，而不是未暂存文件；`privacy-history-check`检查HEAD全部可达历史的路径、提交说明及去重内容，也解析JSON中的转义字符串。两者只读Git对象，不联网、不访问硬件。

pre-commit在提交前检查拟提交内容；pre-push逐个检查实际待推送ref的完整历史，不能只检查新旧ref差集。删除ref无需内容检查。检查输出只报告路径、类别和计数，不复述匹配正文。代码中的`resume`表示恢复运行，不因它与其他词同形就拦截。

发现异常时保留本地原始资料，修改公开版本并重新检查；不要禁用检查、强行加入本地私有文件或使用`--all`/`--mirror`推送备份refs。

历史维护先在隔离副本验证并保留本地备份。历史替换会改变提交ID，需要协调各工作副本；不能将旧历史merge回已维护的分支。实际远程写入前核对目标ref，并用精确旧ref值限制更新范围。

远程ref维护不能保证第三方副本或平台缓存同时消失；相关处理边界见[GitHub历史数据移除说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。
