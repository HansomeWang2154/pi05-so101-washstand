# SO101本机校准操作

更新：2026-10-17。用户决定自行校准，替代此前优先向卖家取得校准JSON的准备路径。本轮只核对源码、手册姿态图和两个校准CLI帮助，没有启动设备或生成真实标定。G0仍待实测。

## 准备与串口确认

一次只校准一只臂；关闭其他遥操作、录制和舵机调试程序，确认实际占用并记录操作者/用途。固定底座，清空活动范围，先支稳从臂；相机不需要接入校准。保持舵机串联接线，校准不需要拆线逐个设ID。不要运行`setup-motors`、重刷固件或猜测端口。

当前驱动按Feetech STS3215、ID1～6握手。资料手册标注HX系列，实际兼容性尚未核验；若出现缺ID、型号不匹配等报错，先保留输出并核对实物/驱动，不绕过检查继续写设备。

```bash
cd "$(git rev-parse --show-toplevel)"
source .venv/bin/activate
ls -l /dev/serial/by-id/
```

若没有稳定路径，分别接入控制板，枚举`/dev/ttyACM*`、`/dev/ttyUSB*`并确认对应关系。插拔控制板USB用于识别端口时先保持机械臂有支撑、无活动控制进程，不带电插拔舵机信号线。只在实际连接终端执行；当前工具会话此前未见设备。

用户采集终端使用`conda activate lerobot`即可，后续命令相同。SDK/串口依赖已按ISSUE-017补齐并通过离线导入/构造检查，参见[硬件依赖摘要](../environment/real-hardware-dependency-summary.json)；不据此视为校准或设备通信通过。

## 主臂校准

以下端口占位符替换为实际值；`washstand_leader`是本次新校准使用的名字，可与项目模板保持一致。明确指定保存目录；如该目录已有同名JSON，先备份，重新校准会改电机标定和覆盖文件。

```bash
python -m lerobot.scripts.lerobot_calibrate \
  --teleop.type=so101_leader \
  --teleop.port='主臂实际串口路径' \
  --teleop.id=washstand_leader \
  --teleop.calibration_dir=$HOME/.cache/huggingface/lerobot/calibration/teleoperators/so_leader \
  --teleop.use_degrees=true
```

按终端阶段操作：

1. 若提示`Press ENTER to use provided calibration ... or type 'c' ...`，输入`c`再回车。本次是重校准，直接回车会复用旧文件。没有此提示就继续看下一步。
2. 出现`Move ... to the middle of its range of motion and press ENTER....`后，手动把各关节置于正常行程中间，夹爪约半开，腕部不扭线，再回车。主从采用对应的初始姿态。可对照资料手册4.1节的两臂姿态图（PDF第42～43页），不要摆成完全折叠或关节极限。
3. 出现范围记录表后，依次缓慢移动`shoulder_pan`、`shoulder_lift`、`elbow_flex`、`wrist_flex`和`gripper`，覆盖各自正常完整可动范围。夹爪正常开合，不夹物体。观察表格MIN/MAX随移动变化；不能只抖动几度。
4. 当前版本明确排除`wrist_roll`腕滚转的范围遍历，其范围自动设为0～4095。不要为了校准让腕部绕线转圈，也不要把“half turn”理解为必须手动旋转半圈。
5. 遇到结构止挡、线缆拉紧或异常阻力就停，不强推。五项全部覆盖后，按Enter结束记录。
6. 看到`Calibration saved to .../washstand_leader.json`才表示文件已保存；不是看到表格就算完成。

## 从臂校准

主臂程序退出后，再执行从臂命令，重复同样交互：

```bash
python -m lerobot.scripts.lerobot_calibrate \
  --robot.type=so101_follower \
  --robot.port='从臂实际串口路径' \
  --robot.id=washstand_follower \
  --robot.calibration_dir=$HOME/.cache/huggingface/lerobot/calibration/robots/so_follower \
  --robot.use_degrees=true
```

从臂启动阶段的连接配置可能短暂启用力矩，之后校准才关闭力矩；不能保证从进程启动起始终可以自由拖动。启动前支稳，看到`Move ... middle`提示后再手动移动，勿与通电保持力对抗。两臂都要完成关节范围记录，包含夹爪。

## 保存与验收

以上显式目录对应文件：

```text
$HOME/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/washstand_leader.json
$HOME/.cache/huggingface/lerobot/calibration/robots/so_follower/washstand_follower.json
```

保留原始JSON、运行日志、日期和文件哈希作为本次标定版本；机器配置与完整标定不放普通Git提交，审核摘要另归档。后续遥操作和录制必须沿用这两个id和目录。参照[遥操作与试采指南](已标定双臂遥操作与试采.md)第2～3节填写变量，确认两臂对应姿态接近后小幅验证六关节方向/范围，再练习完整抓放。保存成功不等于跟随、相机或G0全部通过。

若报`Some motors have the same min and max values`，按报错关节核对是否在范围阶段实际移动，不自行改JSON绕过。其他通信/型号错误保留输出后排查，不反复试写。

## 六电机与五项手动范围的区别（2026-10-18核对）

手动范围记录表不包含5号wrist_roll，因为当前驱动将它按整圈编码范围处理，自动写入0～4095；这是编码计数，不是角度。手动记录的五项为肩偏转、肩俯仰、肘、腕俯仰和夹爪。居中偏移步骤和最后生成/写入/保存标定仍覆盖全部六电机。

已只读确认本机leader/follower两份washstand JSON各六项、id1～6完整，wrist_roll范围均为0～4095；没有重新标定。此核对不替代物理方向、结构/线缆限位验证，不需为补第六行而强转腕部。

源码依据：SOFollower.calibrate与SOLeader.calibrate使用unknown_range_motors排除wrist_roll；SerialMotorsBus.set_half_turn_homings的motors=None默认全部电机。详见ISSUE-022及environment/trial03-recording-summary.json。
