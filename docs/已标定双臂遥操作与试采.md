# 已标定主从臂：遥操作与真实试采

更新：2026-10-17。用户确认两臂由卖家预先校准；本轮核对当前源码和CLI帮助，没有连接设备或录制真实数据。G0/G1仍待实测。本指南用于一主一从，不是双执行臂系统。

用户随后决定自行校准：先执行[SO101本机校准操作](SO101本机校准操作.md)，使用新生成的两个id/目录，再从本文第2节继续。下面第1节保留为复用已有文件时的备用说明，不再把等待卖家JSON当作当前前置任务。

## 1. 先复用原标定

需要六项实际信息：leader端口、follower端口、两个原有id、两个校准文件所在目录。相机接入时再增加top/wrist路径。不要将原id直接替换成项目模板的`washstand_leader/follower`。

卖家预先校准时，先核对交付物：向卖家取得分别对应leader和follower的校准JSON、原两个id，以及其成功运行所用LeRobot版本/厂商驱动和遥操作命令。现有资料包清单未见校准JSON；标定参数可能仍在卖家电脑中。文件拿到后保留原件，以显式目录读取，不自行生成数值。拿不到匹配文件时，先核对厂商支持的读取/导出方式；确实无法复用时，再按本机驱动的引导做一次校准。不要在未知标定状态下试发目标。

当前源码按`<calibration_dir>/<id>.json`读取标定；显式传入`calibration_dir`可复用旧版`so101_leader/follower`目录中的文件，避免当前通用`so_leader/follower`默认目录不同而找不到文件。若校准在另一台电脑完成，需要拿到匹配的两个文件与原命令；“舵机曾校准”不等于当前解释器能找到文件。不要自己重建校准数值。

在实际连接设备的Linux终端运行：

```bash
cd "$(git rev-parse --show-toplevel)"
source .venv/bin/activate
ls -l /dev/serial/by-id/
ls -l /dev/v4l/by-id/
```

若没有稳定别名，实际枚举`/dev/ttyACM*`、`/dev/ttyUSB*`、`/dev/video*`并确认身份；不是照抄这些通配符当端口。按旧命令或校准日志查文件；默认缓存目录可作查找起点：

```bash
find "${HF_LEROBOT_CALIBRATION:-${HF_LEROBOT_HOME:-${HF_HOME:-$HOME/.cache/huggingface}/lerobot}/calibration}" -type f -name '*.json'
```

自定义目录还需另查。本轮工具会话未见默认校准目录、串口/相机设备，不据此判定用户标定丢失或设备故障。

用户后续明确使用已有`lerobot` conda环境，上述激活行可改为`conda activate lerobot`；本机`.venv`复用该环境，两者都需要同一套硬件依赖。2026-10-17已修复ISSUE-017，新增SDK/串口依赖见[版本清单](../environment/real-hardware-requirements.txt)。若在另一台电脑复现，先激活对应环境，再执行`python -m pip install -r environment/real-hardware-requirements.txt`并验证导入；该清单只包含通信依赖，不是完整LeRobot环境。

停止其他标定、预览、遥操作和录制程序，检查实际设备占用；现场记录操作者、用途及停止方式。两臂先处在接近的安全支撑姿态，跟随时再小幅移动leader。停止或断电前让follower处于有支撑的位置；默认断开可能释放力矩。若原流程使用厂商驱动，先核对该驱动和现有LeRobot的兼容性；不能凭机械臂名称替换驱动。

## 2. 填一次变量，检查文件

以下中文字符串均须替换为实际值；不要执行包含占位符的设备命令。`id`是校准文件名去掉`.json`，目录不包括文件名。

```bash
LEADER_PORT='主臂实际稳定端口'
FOLLOWER_PORT='从臂实际稳定端口'
LEADER_ID='原主臂校准id'
FOLLOWER_ID='原从臂校准id'
LEADER_CAL_DIR='主臂校准文件所在绝对目录'
FOLLOWER_CAL_DIR='从臂校准文件所在绝对目录'

test -f "$LEADER_CAL_DIR/$LEADER_ID.json"
test -f "$FOLLOWER_CAL_DIR/$FOLLOWER_ID.json"
```

两个检查都应返回0，再继续。将已确认的本机字段写到忽略的`configs/local.json`；以下LeRobot命令不会自动读取项目JSON，仍须显式传参。

为避免每条命令重复填写，在同一bash终端建立参数数组：

```bash
ROBOT_ARGS=(
  --robot.type=so101_follower
  "--robot.port=$FOLLOWER_PORT"
  "--robot.id=$FOLLOWER_ID"
  "--robot.calibration_dir=$FOLLOWER_CAL_DIR"
  --robot.use_degrees=true
)
TELEOP_ARGS=(
  --teleop.type=so101_leader
  "--teleop.port=$LEADER_PORT"
  "--teleop.id=$LEADER_ID"
  "--teleop.calibration_dir=$LEADER_CAL_DIR"
  --teleop.use_degrees=true
)
```

这里显式选择两侧一致的角度模式，需在下一步核验。若沿用旧流程的`false`模式，两侧同时改为`false`并记录真实范围，后续录制保持一致。当前源码在`true`模式下，五个臂关节按角度处理，夹爪单独映射到0～100；这些是源码行为，实际方向/范围仍需测量。

## 3. 先无视觉遥操作

这是会让follower运动的命令，现场确认两臂和周围状态后运行：

```bash
python -m lerobot.scripts.lerobot_teleoperate \
  "${ROBOT_ARGS[@]}" "${TELEOP_ARGS[@]}" \
  --fps=30
```

沿用匹配校准文件。若提示使用已有校准或输入`c`重新校准，确认文件确实属于该臂后按Enter沿用；若直接提示移动关节重新标定，则先停止并排查文件/id/目录。无需为了遥操作主动运行`setup-motors`或重新写ID。

缓慢检查六个关节对应、正负方向、夹爪开闭，再练习接近→抓取→运输→入杯→松爪→撤臂。这里不录数据；正常结束先停下动作、放稳并支撑从臂，再在控制终端按一次Ctrl+C并等待清理。2026-10-17退出清理补丁已应用，实际卸力仍待现场验收；若有清理异常或关节仍带力矩，支稳后关闭舵机供电，不强掰，也不以拔USB代替断电。见[退出锁力修复](SO101退出锁力与异常清理修复_2026-10-17.md)。异常时优先使用现场已确认的停止方式，不为保存数据延误停止。

## 4. 接入top/wrist，先看画面

确保上一步已结束、设备已释放，再查相机：

```bash
python -m lerobot.scripts.lerobot_find_cameras opencv
```

检查输出图片，按实际画面确认身份；结束独立预览后再启动双相机遥操作。优先使用稳定路径；若只能用数字索引，配置中填数字而非路径字符串，并在重新插拔后重新确认。

```bash
TOP_CAMERA='top实际稳定视频路径'
WRIST_CAMERA='wrist实际稳定视频路径'
CAMERAS="{top: {type: opencv, index_or_path: '$TOP_CAMERA', width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: '$WRIST_CAMERA', width: 640, height: 480, fps: 30}}"

python -m lerobot.scripts.lerobot_teleoperate \
  "${ROBOT_ARGS[@]}" "${TELEOP_ARGS[@]}" \
  "--robot.cameras=$CAMERAS" --fps=30 --display_data=true
```

640×480、30Hz是待验证起点。top固定且不镜像，左右杯按top画面定义；wrist看清夹爪和入杯过程。检查完整动作的可见性、掉帧、延迟和腕相机净空。帧率不稳先排查USB带宽/连接、图像处理和写盘，必要时固定降低频率并记录；不要仅改数据集fps标签。检查通过后用Ctrl+C结束遥操作，不能让它与录制同时占设备。

## 5. 第一条真实录制

2026-10-17用户指定的red_left单条本机启动器已准备，直接操作见[单条红牙刷左杯试采](单条红牙刷左杯试采.md)。录制入口清理补丁0002已应用并离线验证，实际数据/卸力仍待验；下文通用参数模板保留。

先按[真实会话模板](../templates/real_session.md)创建会话记录，确认六维名称/顺序、单位、夹爪范围、绝对目标语义和观测/动作先后。当前源码先读follower观测，再读leader目标并发送；时间戳不等于两路相机严格硬同步，需实测图像与动作对应。

本版若启用`max_relative_target`裁剪，保存的action可能仍是裁剪前目标，见ISSUE-016。不要为规避该问题取消现场必需的限制；若需要裁剪，先解决/验证实际发送动作的记录，不能直接将其当已核验契约。

先摆好物体和两臂初始姿态。当前录制器连接后直接开始，不等待Enter。首条已证实同步Rerun会阻塞控制，采集命令关闭实时显示，两路相机视频仍保存，之后离线查看。一次录一条：

```bash
SESSION_ID="real_$(TZ=Asia/Shanghai date +%Y%m%d_%H%M%S)_trial01"
DATASET_ROOT="$PWD/data/real/$SESSION_ID"
REPO_ID="local/$SESSION_ID"
TASK='Put the red toothbrush into the left cup.'
mkdir -p "outputs/real/$SESSION_ID"
cp templates/real_session.md "outputs/real/$SESSION_ID/session.md"

python -m lerobot.scripts.lerobot_record \
  "${ROBOT_ARGS[@]}" "${TELEOP_ARGS[@]}" \
  "--robot.cameras=$CAMERAS" --display_data=false \
  "--dataset.repo_id=$REPO_ID" "--dataset.root=$DATASET_ROOT" \
  --dataset.no_stamp=true --dataset.push_to_hub=false \
  --dataset.fps=30 --dataset.num_episodes=1 \
  --dataset.episode_time_s=45 --dataset.reset_time_s=30 \
  --dataset.rgb_encoder.vcodec=h264 \
  "--dataset.single_task=$TASK"
```

不要提前创建`DATASET_ROOT`本身；首次创建要求它不存在。`local/...`只是本地数据标识，不要求登录或上传。结束后等待编码和保存完成，不立即拔USB。录制不需要加载pi05或租云端GPU。

完整演示：开始姿态→抓指定牙刷→放指定杯→松爪→撤离→稳定至少2秒。提前完成后按`q`正常结束并保存当前片段；45秒期限在循环边界检查，遇阻塞不保证准时退出；不能当硬件急停。若失败，在能安全退出时同样保存，随后在会话记录中标为失败/排除，不能混入成功示范。

| 按键 | 当前版本效果 |
|---|---|
| `q` / Esc | 正常停止本次运行，保存当前已有片段，然后整理文件/断开；不是硬件急停 |
| `n` / → | 提前结束当前阶段；若还有后续条目则进入reset；最后一条直接保存结束 |
| `r` / ← | 丢弃当前片段并重录；会清临时图像，本项目保留失败时不用 |
| Enter | 录制阶段没有开始/保存功能，仅按校准提示使用 |
| Ctrl+C | 中断；当前未保存片段可能丢失，已保存条目仍整理；不能承诺保留失败视频 |

需在真实交互终端运行；关注启动时键盘监听是否生效。无TTY的流水线运行可能只有计时器。reset期间仍会跟随leader，且不是暂停等待确认；首轮一次一条可以避免自动开始下一条。

## 6. 续录、换任务和QA

同一个终端保留`REPO_ID/DATASET_ROOT`。正常完成第一条后，使用同一套录制命令，增加`--resume=true`，保留相同根目录、repo_id、相机、单位、fps等。`num_episodes=1`表示本次再加一条；不用重新生成SESSION_ID，也不删除目录。

换任务只替换`TASK`，每次运行的所有episode都用同一字符串：

| 条件 | TASK精确字符串 |
|---|---|
| red_left | Put the red toothbrush into the left cup. |
| red_right | Put the red toothbrush into the right cup. |
| blue_left | Put the blue toothbrush into the left cup. |
| blue_right | Put the blue toothbrush into the right cup. |

建议先每条件一条，共4条，检查后再按同一契约补齐10～20条；熟悉流程后才将单次新增数改为多条。用session/layout/episode清单记录每条task及结果，防止口头任务与写入字符串不一致。若改了相机/单位/契约，开新版本，不向旧集续录。

试采QA包含关键帧、视频全量解码/帧数对应、NaN/Inf、时间戳、实测频率和丢帧、state/action曲线、突跳/限位、夹爪方向、图像动作对齐与episode边界。现有项目元数据检查不能替代这些完整QA，待真实数据到手后执行并归档。先检查3～5条，再继续；失败/中断注明排除原因，原始数据不清理。训练统计由训练侧按冻结的训练episode复核。
