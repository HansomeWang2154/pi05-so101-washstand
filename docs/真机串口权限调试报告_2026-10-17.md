## 修复步骤（需用户在本机终端执行）

根据已确认的设备组和账户，用户已执行下列两条完整修复命令，当前无需重复：

```bash
sudo usermod -aG dialout "$(id -un)"
sudo setfacl -m "u:$(id -un):rw" /dev/ttyACM0 /dev/ttyACM1
```

第一条为后续会话加入串口访问组，`-a`保留现有附加组。第二条仅对当前两个设备节点授予该用户读写ACL，让旧会话立即可用；重新插拔后该ACL通常不会保留，不能把它当作持久修复。

完整注销桌面再重新登录会刷新组；仅开新终端可能仍继承旧桌面组。若暂不注销，也可在终端运行`newgrp dialout`进入新子shell，在其中确认`id`包含dialout、重新激活conda。它不会更新父终端或现有Codex进程的组。

sudo密码只在本机终端输入，不发送到聊天。这里不使用`chmod 666`，也不用root身份运行LeRobot。本轮未停止ModemManager、修改udev规则或重设电机参数；当前证据不支持这些操作。
