# π₀.₅ × SO101：语言条件洗漱用品整理

本项目研究语言条件下的SO101洗漱用品整理：使用完整 π₀.₅ 预训练权重，在 SO101 真实示范上微调，完成云端策略推理、本地机器人执行与可复现评测。

**新对话接续真机/采集工作：先读[项目记忆与真机交接](docs/项目记忆与真机交接.md)和[跨对话协作约定](docs/跨对话协作约定.md)。** 已确定的硬件和模型路线、当前证据、G0/G1入口及可复制的启动提示均在交接文档中。

项目按环境、数据、训练、部署和评测里程碑推进；执行状态以实际证据为准。

## 已确定的范围

- 一个干燥的洗漱台桌面主题，一个抓取放置任务家族。
- 标准目标：红/蓝牙刷 × 左/右杯，四种指令条件；两支牙刷、两个杯子同时出现。
- 最小目标：一支指定牙刷放左杯/右杯，两种指令条件，保留同布局换指令测试。
- 完整 `lerobot/pi05_base` 初始化；首轮 expert-only 微调，具体解冻参数需实查。
- 本地开发和数据采集；A800 80GB 训练；4090 云端推理先实测再使用。
- 真机主线必须完成；本地 MuJoCo 仿真列为可选模块，通过轨迹与数据校验后才开展 sim+real 训练对照。
- 首版不安排多个 VLM、牙膏操作、多步骤整理、量化或自研 RTC。

这四种条件共享同一种抓放技能，不对外宣传为四种独立操作技能。首版只主张固定指令下的条件执行，不预先主张开放式语言泛化。

## 初始化后的使用入口

```bash
source .venv/bin/activate
washstand doctor --gpu
washstand validate-config
washstand plan train
washstand status
make test
```

未激活环境时可用 `python3 scripts/project.py --help`。项目准备工具仅用标准库，模型/硬件运行时单独核验。`plan`只生成命令预览；默认串口、相机编号、数据ID和检查点仍为空，不会自动猜测、训练、上传或控制机械臂。

本机配置复制 `configs/local.example.json` 为 `configs/local.json` 后填入，保留公共配置可复现。环境快照和实际初始化验收见开发日志；主线状态另存 `project_status.json`。

## 本地与云端的协作约定

本项目在 `pi05-so101-washstand/` 内独立使用 Git，默认分支 `main`。每个完成的改动经检查后提交；数据、权重、本机配置及详细环境输出被忽略。当前远程仓库尚未配置，具体约定见 [Git版本管理](docs/Git版本管理.md)。

- 本地保留代码、数据主副本、配置、日志和结果；云端作为可替换计算节点。
- 代码用 Git 提交关联；视频/数据用增量同步；模型和训练状态单独存储。
- 每个实验记录代码提交、LeRobot 提交、基础模型 revision、数据划分和完整有效配置。
- 云端释放前检查工件是否已写入可持续保存的位置；GPU、磁盘、传输费用分别记录。
- 不上传凭据；公开数据、模型和仓库前再处理发布范围。
